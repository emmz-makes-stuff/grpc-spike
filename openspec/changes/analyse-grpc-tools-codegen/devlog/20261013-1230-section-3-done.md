Provisional reading, for §4 to design against:
- **Tier A, hot path (a generator alone could fix):**
  - M-01/M-02: oneof scalar boxing, including re-boxing on Clone/Merge;
  - M-14: oneof-message merge allocates an extra object;
  - M-18: O(depth²) re-sizing on nested writes; a size cache, possibly needing Tier B help;
  - M-24: eager `RepeatedField` per field;
  - M-25: Clone's copy constructor chains `: this()`, allocating and discarding every collection.
- **Notable Tier B:**
  - M-03–M-05: maps (LinkedList node per entry; three objects per empty map field; boxed enumerator);
  - M-10: temporary `byte[]` for strings crossing an `IBufferWriter` segment, which is the gRPC write
    path;
  - M-12: empty-but-present bytes;
  - M-16: repeated growth by doubling;
  - M-20/M-22: `ParseFrom(byte[])` and `ToByteArray` allocate a stream object;
  - M-26/M-27: unknown fields.
- **Hypothesis 8 is provisionally rejected.** The generated marshaller already takes the pooled/no-copy
  paths (S-01, S-05, S-24, S-25, S-32, S-33). Per-call cost is grpc-dotnet/HTTP (Tier B).
- No allocation site was found for struct wrappers (M-28) or proto3 `optional` (M-29). M-30 (descriptors,
  parser, codecs) is one-off.
